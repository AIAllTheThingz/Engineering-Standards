# Engineering Standards v1.2.1

## Summary

Version `1.2.1` is a backward-compatible patch release for the published `1.2` governance line. It repairs reusable-workflow identity handling for annotated release tags, hardens the corresponding provenance record, and incorporates the post-`v1.2.0` release-state and behavior-verifier corrections without changing downstream governance obligations.

## Fixed

- Repaired reusable governance workflow identity validation for annotated semantic-version release tags. GitHub's immutable tag-object SHA is verified against the exact `refs/tags/v<semver>` object, the tag must be annotated, and its peeled commit must match the checked-out trusted standards commit.
- Preserved exact commit binding for direct 40-character workflow pins while continuing to reject branch refs, lightweight tags, malformed refs, unexpected repositories, unexpected workflow paths, mismatched tag objects, and tags that peel to a different commit.
- Added explicit workflow identity evidence that records both the GitHub workflow object SHA and the peeled standards commit SHA while keeping existing completion-evidence commit semantics intact.
- Versioned the downstream compatibility document to schema `1.2.0` so a prepared release can represent canary validation honestly: `Passed` requires a full immutable canary SHA, while `Failed`, `Blocked`, `NotRun`, and `NotApplicable` require the canary authority to remain null.
- Corrected release and compatibility guidance after `v1.2.0` so the historical governance-1.1 canary authority is not presented as a complete 1.2 workflow distribution.
- Migrated the `enterprise-powershell` aggregate behavior-evidence gate to the existing dual-profile Actions verifier while preserving fail-closed lifecycle enforcement and human-adjudication requirements.

## Compatibility

The patch does not intentionally change downstream obligations or the central workflow interface.

- Central governance workflow interface remains `1.0.0`.
- Project-manifest schemas remain `1.0.0`, `1.1.0`, and `1.2.0`.
- Test-evidence schemas remain `1.0.0` and `1.1.0`.
- Completion-result schemas remain `1.0.0` and `1.1.0`.
- Downstream compatibility document schemas remain backward compatible at `1.0.0` and `1.1.0`; new schema `1.2.0` adds explicit canary-validation lifecycle state without changing downstream governance requirements.
- Published `v1.2.0` remains immutable historical evidence and is not moved, rewritten, or deleted by this release.

## Security And Trust Boundary

The reusable workflow continues to run with read-only repository contents permission. Caller content remains separated from trusted standards tooling. The annotated-tag repair does not accept moving branches or lightweight tags as release identity and does not weaken repository, workflow-path, object-SHA, or peeled-commit verification.

## Release Validation

Release approval remains bound to one immutable final candidate through the repository lifecycle gate. The approved candidate must pass repository Governance CI, controlled-failure proof, the complete five-scenario external downstream canary matrix, independent artifact verification, and attributable human review before publication. Publication and PostRelease verification remain separate external-state gates.

## Release Integrity

The GitHub Release body for `v1.2.1` must be published from this reviewed file exactly. Do not use GitHub auto-generated release notes or substitute a generated `What's Changed` body. The lifecycle Publication gate verifies the published body hash against this reviewed release-note content.

## Historical v1.2.0 Follow-Up

Issue #103 records the two defects discovered after `v1.2.0` publication: annotated-tag reusable-workflow identity handling and release-note body integrity. This patch provides the governed corrective path while preserving `v1.2.0` as historical evidence.
